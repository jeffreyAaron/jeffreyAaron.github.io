## Part A.2: Recover Homographies

Our goal is to use hand picked points to compute the 3x3 homography matrix. In order to do that, we must construct the matrix below which represents the system of equations that you get after multiplying all the terms of the 3x3 homography matrix with x, y, 1 and solve for x' and y'. Since there are 8 unknowns (the bottom right entry of H can be fixed to 1), we need 4 pairs of points yielding 8 equations.

```python
def computeH(im1_pts, im2_pts):
    n = len(im1_pts)
    A = np.zeros((2*n, 8), dtype=float)
    b = np.zeros(2*n)
    for i in range(n):
        x = im1_pts[i][0]
        y = im1_pts[i][1]
        xprime = im2_pts[i][0]
        yprime = im2_pts[i][1]
        A[2*i] = [x, y, 1, 0, 0, 0, -x*xprime, -y*xprime]
        A[2*i + 1] = [0, 0, 0, x, y, 1, -x*yprime, -y*yprime]
        b[2*i] = xprime
        b[2*i + 1] = yprime

    H = np.linalg.lstsq(A, b)[0]

    H = np.concat([H, [np.ones_like(H[0])]])

    H = np.reshape(H, (3, 3))

    return H
```

## Part A.3: Warp the Images

### Nearest Neighbor

#### Find the bounds of the warped image

```python
def warpImageNearestNeighbor(im, H):
    height, width, channels = im.shape

    # find the bounds
    topleft = H @ [0, 0, 1]
    topRight = H @ [width, 0, 1]
    bottomLeft = H @ [0, height, 1]
    bottomRight = H @ [width, height, 1]

    corners = np.array([topleft, topRight, bottomLeft, bottomRight]).T
    corners = corners[:2] / corners[2]

    xmin, ymin = np.floor(corners.min(axis = 1)).astype(int)
    xmax, ymax = np.ceil(corners.max(axis = 1)).astype(int)
```

#### Create the output image

We create the output image as the largest values that we get from mapping the corners. We also ensure to use H_inv to do inverse mapping. This prevents empty holes in the image.

```python
    out_width, out_height = xmax-xmin + 1, ymax-ymin + 1

    image_out = np.zeros((out_height, out_width, channels))

    alpha = np.zeros((out_height, out_width))

    H_inv = np.linalg.inv(H)
```

#### Map each output pixel back to the source

```python
    for y in range(ymin, ymax + 1):
        for x in range(xmin, xmax + 1):
            # (x, y) to sourceImage
            out = H_inv @ np.array([x, y, 1])
            source_x = out[0]/out[2]
            source_y = out[1]/out[2]
```

#### Round to the nearest pixel and copy it

This implements the Nearest Neighbor selection. We round the mapped source pixel to an integer which effectively just chooses the nearest pixel.

```python
            # nearestNeighbor
            nn_x = np.round(source_x).astype(int)
            nn_y = np.round(source_y).astype(int)

            # ensure valid
            if (nn_x >= 0 and nn_x < width and nn_y >= 0 and nn_y < height):
                alpha[y-ymin, x-xmin] = 1 # alpha high only if the pixel is valid
                image_out[y - ymin, x - xmin] = im[nn_y, nn_x]

    return image_out, (xmin, ymin, out_width, out_height), alpha
```

### Bilinear

In order to interpolate in a bilinear fashion, most of the code is the same. However, when we finally map from source to output, we find the mapped pixel plus one to the right, one below, and one diagonal. This gives us 4 points of data which helps with thin features that must stay continuous. After we have the 4 points, we must interpolate them based on how close the raw (decimal) pixel mapping was to the integer pixel mapping. I created a `lerp` helper function for this that linearly interpolates between two values.

The bilinear version takes about 50 percent longer. This is faster than I expected considering the amount of points that we are fetching.

Surprisingly, the nearest neighbor algorithm left a lot of white splotches around boundaries. In the comparison below, you can see a faint border around parts of the robot where the two different colors meet.

## Part B.2: Feature Descriptor Extraction

The feature descriptor is pretty straightforward:

- We first blur the image to reduce noise from affecting results.
- We sample every `step` point to output an image of the desired patch size.
- We normalize the patch by subtracting its mean and dividing by its standard deviation. This makes the descriptor ignore differences in brightness and contrast between the two images.
- We convert the patch to a single vector by flattening it.

This is our embedding for the point. It represents what the point looks like and allows us to easily tell how similar two points are.

```python
def get_descriptors(grayscale_image, coords, sigma = 2, blur_window = 40, patch_size = 8):
    blurred = skimage.filters.gaussian(grayscale_image, sigma=sigma)
    step = blur_window // patch_size
    middle = blur_window // 2

    descriptors = []

    for i in range(len(coords[0])):
        y, x = coords[0][i], coords[1][i]
        patch = blurred[y-middle : y+middle, x-middle : x+middle]
        patch = patch[::step, ::step]
        patch = patch - np.mean(patch)
        patch = patch / (np.std(patch) + 1e-8)
        descriptors.append(patch.flatten())
    return np.array(descriptors)
```

## Part B.3: Feature Matching

For the feature matching, I wrote a function that takes in two descriptor arrays from two different images. Then it uses the given dist2 function to compute the distances between every pair of descriptors. To compare descriptor X from image 1, we look at the Xth row and then get the 2 smallest values in that row. These are the two closest descriptors in image 2.

Then we apply the ratio test. We divide the distance to the closest descriptor (d1) by the distance to the second closest (d2). If a point has a true match, d1 should be much smaller than d2, so the ratio is small. If d1 and d2 are about the same, the first point is not that much better than the second so we throw it out. We only keep the matches where the ratio is below the threshold of 0.3. The function returns the indices of the matching descriptors in both images.

To choose the threshold, I looked at the graph and saw that the paper tested a threshold of 0.3. From the graph, this seem at the midpoint between a valid feature and an outlier.

```python
def matchFeatures(descriptors1, descriptors2, threshold=0.3):
    distances2 = harris.dist2(descriptors1, descriptors2)
    distances = np.sqrt(np.maximum(distances2, 0))

    twoClosest = np.argsort(distances, axis = 1) [:, :2]
    rows = np.arange(distances.shape[0])
    d1 = distances[rows, twoClosest[:, 0]]
    d2 = distances[rows, twoClosest[:, 1]]
    mask = d1/d2 < threshold

    image1_indices = np.where(mask)[0]
    image2_indices = twoClosest[image1_indices, 0]
    return image1_indices, image2_indices
```

## Part B.4: RANSAC for Robust Homography

In order to get good quality matches and remove outliers, we apply the RANSAC method. I remember when I first heard of this, it seems like a very complicated and scary thing to implement. However, the method was a lot more simpler than I thought. It involves samples of 4 pairs (so we can get a set of the min 8 equations to solve homography). We then take the pairs and fit a homography. We compare the distance of the projected points to the actual way points and then cut any that don't meet our threshold. We keep repeating this for many iterations and keep track of which one provided us a solution using the most number of inliers.

```python
def ransac_filter(keypoints1, keypoints2, threshold=10, max_iterations=100):
    num_matches = len(keypoints1)
    best_matches = None
    best_matches_count = 0
    best_inliers = np.zeros(num_matches, dtype=bool)
    best_H = None
    iterationCount = max_iterations
    for i in range(iterationCount):
        random_indices = np.random.choice(num_matches, size=4, replace=False)
        random_matches1 = keypoints1[random_indices]
        random_matches2 = keypoints2[random_indices]
        H = computeH(random_matches1, random_matches2)
        points = np.hstack([keypoints1, np.ones((len(keypoints1), 1))])
        projected_points = points @ H.T
        projected_points = projected_points[:, :2]/projected_points[:, 2:3]

        errors = np.linalg.norm(projected_points - keypoints2, axis=1)
        inliers = np.where(errors < threshold)[0]
        if len(inliers) > best_matches_count:
            best_matches_count = len(inliers)
            best_inliers.fill(False)
            best_inliers[inliers] = True
            best_H = H

    H_out = computeH(keypoints1[best_inliers], keypoints2[best_inliers])
    return best_inliers, H_out
```

Comparing the manual and the automatic mosaics, I think that the manuals only slightly worse than the automatic ones. When I chose points for the manual ones, I could find myself doing a similar iterative proceses to determine which points were the best to keep to get the best output. Especially for the vertical one. With the automatic method, RANSAC is able to try many different combinations and keep the points that work. Also, it oftens keeps much more points than I kept when I did it manually.
