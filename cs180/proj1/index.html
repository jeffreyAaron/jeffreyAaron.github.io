Single-scale alignment (Euclidean distance, Sum of Squared Differences)

To implement single scale alignment, I wrote the align_single_scale function. First, I used a nested for loop to iterate through all possible shifts in x and y within the frameDim window of 15 pixels. To shift each image, I used the np.roll function. Then I ensured to crop the output of the roll and b (the target to align to) to account for the fact that after rolling, certain pixels will be cut off. The SSD function calculates similarity between the two images by summing the differences. This assumes that the point on the image in one color channel shares a similar brightness as on the other color channels. However, images are meant to be vibrant with color and this method can break down with very colorful images I predict.

Single-scale alignment with NCC

Next, we try a new scoring function to rank the similarity between the color channel alignments. NCC first starts by normalizing the brightness of each image by subtracting the mean. Then we divide each by its own norm to make the range of values between -1 and 1. Finally, we take the dot product of the two color channels to get a measure of how different the two “vectors” are. Larger number = better correlation. To reduce the amount of code that I implemented, I edited the single_scale_alignment function to take in a scoreFunc param. This way, I can adjust the how the candidates are ranked. Because of this change, the NCC function must be negated because the single_scale_alignment function defaults to minimize the scoreFunc.

Multi-scale pyramid alignment

After getting good results with single scaling alignment, I wanted to try a method that would work on larger images. The current single scaling aproach would be too compute intensive for the larger images. The search grid increased quadratically in time needed as we expand the grid. So to alleviate this issue, we can use an image pyramid to downscale the image. Then perform our previous single scale search on that smaller image. Then we undo the scaling and move to the next level. One thing that got me at first was forgetting the double the offset that the lower level found. This causes the image to drift slightly off from where it should be. Another issue I faced was that the 14 sammple images were different sizes. So instead of using a fixed number of levels, I made the image pyramid shrink the image dimension until the smallest dimension was under a set size. I also continued with good programming practices by adding a shift and crop helper function and allowing the align_pyramid function to take in a function for the finer single scale alignment. Because NCC performed a little better above, I chose to use that as my scoring function.

emir.tif is the one image that failed to align (of 17). I think this is because of how color full the robe is. Each fully saturated color has a unique pattern in its respecive image channel. This makes it hard to align. I think it would be better to use some kind of edge detector. However, for this assignment, I was able to get away with only using the green channel as the anchor. I think this is because the background has more green and the other channels are able to aligne to the non colorful background better.
